# Сайт стартап-проекта «ЦИФРОЛЕС»

Статический одностраничник: `index.html` (вся вёрстка и стили внутри файла, без внешних скриптов, шрифтов и CDN) и папка `img/` с логотипами и скриншотами. Работа 5 Календарного плана договора № 913ГССС27/107030 от 15.10.2025 (программа «Студенческий стартап», Фонд содействия инновациям).

Проект реализован при поддержке Фонда содействия инновациям в рамках программы «Студенческий стартап» мероприятия «Платформа университетского технологического предпринимательства» федерального проекта «Технологии».

## Логотипы: заменить на официальные

Сайт fasie.ru отдаёт curl-запросам только страницу-заглушку с кодом 403, поэтому официальные файлы скачать автоматически не удалось. В `img/` лежат временные SVG с текстом. Перед публикацией:

1. Открыть в браузере https://fasie.ru/press/ (раздел «Пресс-центр», логотипы и фирменный стиль) и скачать официальные логотипы Фонда содействия инновациям, федерального проекта «Технологии» и «Платформы университетского технологического предпринимательства» (PNG или SVG на светлом фоне).
2. Сохранить их в `img/` под теми же именами и расширениями, либо под новыми именами `logo-fasie.png`, `logo-technologii.png`, `logo-putp.png`.
3. Если расширение изменилось, поправить шесть ссылок в `index.html` (по три в `<header class="support">` и `<footer class="support">`): `img/logo-fasie.svg` → `img/logo-fasie.png` и так далее.
4. Проверить, что в шапке логотипы не ниже 48 px по высоте (стиль `.support .logos img { height: 56px }`, на телефоне 48 px).

## Публикация на GitHub Pages

1. Создать репозиторий на GitHub, например `cifroles` (публичный, иначе Pages недоступен на бесплатном тарифе).
2. Загрузить в корень репозитория содержимое этой папки: `index.html`, `img/`, `README.md`. Через терминал:

   ```bash
   cd /Users/ildar/work/lifeAgent/projects/grant/reports/06-site
   git init
   git add index.html img README.md
   git commit -m "Сайт проекта ЦИФРОЛЕС"
   git branch -M main
   git remote add origin https://github.com/<user>/cifroles.git
   git push -u origin main
   ```

3. В репозитории открыть Settings → Pages. В блоке «Build and deployment» выбрать Source: «Deploy from a branch», Branch: `main`, папка `/ (root)`, нажать Save.
4. Через 1-3 минуты сайт откроется по адресу вида `https://<user>.github.io/cifroles/`. Адрес показывается в том же разделе Settings → Pages.
5. Проверить страницу на экране 1366×768: логотипы и текст поддержки видны без прокрутки; открыть с телефона.
6. Записать итоговый адрес в `reports/FACTS.md` (строка «Сайт: адрес [уточнить после публикации]») и в отчёт о развитии.

Если репозиторий назван `<user>.github.io`, сайт будет доступен по адресу `https://<user>.github.io/` без подпапки.

## Как сменить домен

1. Купить домен (например, `cifroles.ru`) у регистратора. Домен можно оформить на ООО «ЦИФРОЛЕС» или на физлицо; если оплачен собственными средствами физлица, в финансовый отчёт по гранту его не включать.
2. У регистратора создать DNS-записи:
   - для корневого домена четыре записи `A` на адреса GitHub Pages: `185.199.108.153`, `185.199.109.153`, `185.199.110.153`, `185.199.111.153`;
   - для `www` запись `CNAME` на `<user>.github.io`.
3. В Settings → Pages в поле «Custom domain» ввести домен, нажать Save, дождаться проверки DNS и включить «Enforce HTTPS». GitHub сам добавит в репозиторий файл `CNAME`.
4. Старый адрес `https://<user>.github.io/cifroles/` будет перенаправлять на новый домен.

## Напоминания для отчёта

- **Хостинг не менее 15 месяцев.** Сайт должен быть доступен весь срок проверки отчётности, с запасом не менее 15 месяцев после сдачи отчёта (ориентир: до начала 2028 года). GitHub Pages бесплатен; если переходить на свой домен, продлевать его заранее.
- **Скриншот шапки.** После публикации сделать скриншот страницы по итоговому адресу так, чтобы в кадре были адресная строка браузера, три логотипа и текст поддержки. Сохранить как `img/screenshot-00-header.png` и приложить к отчёту (раздел 1.5 отчёта: только ссылка и итог).
- **Текст п. 7.2** на странице присутствует дважды, в шапке и в подвале, дословно. При любых правках текст и логотипы не удалять. Та же фраза обязательна в README программы и во всех публикациях о проекте.
- Ссылку на сайт внести в отчёт о развитии (строка «сайт») и в `projects/grant/state.md`.
